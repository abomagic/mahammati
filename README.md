# مهمّتي — نسخة حقيقية مبدئية

هذه النسخة ليست مجرد واجهة LocalStorage:
- حسابات مستخدمين محفوظة في SQLite.
- كلمات المرور مجزأة باستخدام scrypt.
- جلسات دخول منفصلة.
- مهام حقيقية ينشرها الأدمن بسعر منخفض.
- إجابة المستخدم تدخل "قيد المراجعة".
- لا تُضاف المكافأة إلا بعد اعتماد الأدمن.
- محفظة برصيد متاح + رصيد محجوز.
- بيانات سحب: InstaPay / محفظة موبايل / بنك / PayPal.
- طلب السحب يحجز المبلغ فورًا حتى لا يُصرف مرتين.
- الأدمن يسجل مرجع التحويل الحقيقي بعد إرسال المال فعليًا.
- إذا رفض الأدمن طلب السحب يعود المبلغ للرصيد.

## التشغيل

1. ثبّت Node.js 20+.
2. انسخ `.env.example` إلى `.env` ثم غيّر بيانات الأدمن والسر.
3. لأن Node لا يقرأ `.env` تلقائيًا في كل الإصدارات، يمكنك تشغيل القيم كمتغيرات بيئة،
   أو استخدام مدير استضافة يدعم Environment Variables.
4. نفّذ:
   npm install
   npm start
5. افتح:
   http://localhost:3000

## بيانات الأدمن الافتراضية للتجربة
- البريد: admin@example.com
- كلمة المرور: ChangeMe123!

غيّرها قبل النشر العام.

## مهم جدًا قبل إطلاق أموال حقيقية
- استخدم HTTPS.
- ضع قاعدة البيانات على خدمة مُدارة أو PostgreSQL عند التوسع.
- فعّل Rate Limiting وCSRF/حماية الجلسات وسجل تدقيق Audit Log.
- ضع شروط استخدام وسياسة خصوصية وسياسة نزاعات.
- تحقّق من هوية المستخدمين عند الحاجة، ومن قوانين العمل/الضرائب/مكافحة غسل الأموال في بلد التشغيل.
- موّل المنصة فعلًا قبل اعتماد المهام؛ لا تضف أرصدة بلا غطاء نقدي.
- لا تجعل زر "تم الدفع" متاحًا إلا لموظف مالي موثوق.
- أفضل إطلاق أولي: تحويل يدوي حقيقي عبر InstaPay/البنك/المحفظة ثم تسجيل المرجع.
- للربط الآلي لاحقًا، استخدم مزود Payouts يدعم بلد شركتك والمستلمين، وأضف مفاتيح API في الخادم فقط، لا في الواجهة.

## ملاحظة عن السحب
الكود الحالي يدير طلبات سحب حقيقية محاسبيًا، لكنه لا يستطيع إرسال مال من حسابك من تلقاء نفسه:
أنت تحتاج حسابًا تجاريًا ممولًا لدى البنك/المحفظة/مزود الدفع ومفاتيح/صلاحيات API.
حتى يتم ربط ذلك، الأدمن يحول المال فعليًا خارج الموقع ثم يضغط "تم الدفع" ويسجل المرجع.
